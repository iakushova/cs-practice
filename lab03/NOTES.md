# Lab 03 — Git workshop

## 1. Три состояния проекта

Проект развивался тремя отдельными коммитами:

- `Add calculator addition` — добавлено сложение;
- `Add subtraction to calculator` — добавлено вычитание;
- `Add multiplication to calculator` — добавлено умножение.

Каждое изменение было сохранено отдельным коммитом.

## 2. Сравнение версий и поиск изменений

### git log --oneline --stat

Показывает историю коммитов в сокращённом виде.

Параметр `--stat` дополнительно показывает статистику изменений:
какие файлы изменялись и сколько строк было добавлено или удалено.

### git diff HEAD~2 HEAD -- lab03/calc.py

Показывает различия между двумя состояниями файла.

В этой работе команда сравнила состояние `calc.py` два коммита назад
с текущим состоянием и показала добавленные строки вычитания
и умножения.

### git show HEAD~1

Показывает конкретный коммит, его автора, дату, сообщение
и изменения, которые были внесены этим коммитом.

В этой работе `HEAD~1` указывал на коммит `Add subtraction to calculator`.

### Разница между git diff, git show и git log

`git log` показывает историю коммитов.

`git show` показывает конкретный коммит вместе с его изменениями.

`git diff` сравнивает два состояния и показывает различия между ними.

### git log -S"def" --oneline -- lab03/calc.py

Опция `-S` ищет коммиты, в которых изменилось количество
вхождений указанной строки.

В нашем `calc.py` строки `def` пока нет, поэтому команда не нашла
подходящих коммитов.

### git blame lab03/calc.py

Показывает для каждой строки файла коммит и автора,
которые последними изменили эту строку.

С помощью `blame` можно узнать происхождение конкретной строки
и найти коммит, в котором она появилась или была изменена.
## 3. Восстановление файла

`git restore lab03/calc.py` восстанавливает файл из текущего `HEAD`.
Я проверил это, удалив несколько строк из `calc.py` без коммита, а затем
выполнив `git restore lab03/calc.py`.

`git restore --source=<commit> lab03/calc.py` позволяет взять файл из
конкретного коммита и поместить эту версию в рабочую папку. При этом
вся ветка не переключается.

Если выполнить `git restore` для файла с полезными незакоммиченными
изменениями, эти изменения будут потеряны.
## 4. Ошибочный коммит и его отмена

Я добавил деление без проверки деления на ноль и создал коммит
`Add division without zero check`. Затем выполнил `git revert HEAD`.

`git revert` не удаляет ошибочный коммит из истории. Он создаёт новый
коммит, который отменяет изменения предыдущего коммита.

`git reset --hard` может передвинуть указатель текущей ветки на другой
коммит и удалить коммиты из текущей истории. Также он может удалить
незакоммиченные изменения в рабочем каталоге.

Для опубликованной истории безопаснее использовать `git revert`,
потому что история не переписывается: ошибочный коммит остаётся,
а его отмена записывается отдельным новым коммитом.
